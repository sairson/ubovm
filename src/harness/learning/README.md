# Agent 后台自主学习

核心实现位于 `src/harness/learning/`（原 `agents/knowledge/`），由 `createInternalTools`（`intools/runtime.mjs`）接入 Worker 和协作对话。**无需用户主动调用，也不要求前台 Agent 调用学习工具。** 不修改模型权重。

本目录与 `intools/note/`（会话笔记工具）无关：笔记是前台结构化记忆；此处是工具执行证据驱动的被动学习。

## 自动流程

1. `onToolResult` 在同一个事务里保存执行证据和学习任务，再唤醒后台队列；前台不等待模型反思。进程在两个步骤之间退出，也不会丢失任务。
2. 自动生成工具使用经验：输入字段结构、成功/失败统计、失败后恢复时需要检查的条件。基础规则不复制参数值和原始输出到共享库。
3. 桌面启用可选的后台模型反思：从同一 worker 最近 8 条证据提炼通用方法，至少 3 条记录才触发；具有指纹的新记录还要求至少两种不同观察和此前未反思的新观察，完全重复的调用不消耗反思预算。模型同时读取最多 4 条、合计最多 8192 字符的历史方法，比较失败原因、适用条件、具体修正和结果验证。模型不携带工具，只能输出候选方法 JSON；成功和失败引用均由宿主核对。
4. 自动保存方法、发布适合跨任务复用的通用方法。工具使用经验只向步骤完全一致的版本反馈后续成功；失败反馈关联最新匹配的工具方法。修正后的成功不能给旧失败版本刷成绩；不会把任意语义方法假定为已被使用。
5. 每轮上下文自动检索并注入相关经验。后台生成的方法始终是候选参考，不替代当前任务验证，不扩展权限。

学习工具 `learn_capability` 作为内部管理接口保留，默认不加入前台工具清单。`self-learning` 技能仅解释如何理解经验，后台流程不依赖该技能是否已加载。

## 存储建议与实现

| 方案 | 适用情况 | 实现 |
| --- | --- | --- |
| `~/.ubovm/learning/` | 跨工作区、跨会话复用通用经验 | 桌面默认保存到 `knowledge.sqlite` |
| 固定工作区 `.learning/` | 限定项目范围 | 把 `libraryFile` 配成该目录下数据库的绝对路径 |
| `skills/self-learning` | 可发现的说明入口 | 使用现有内置技能安装流程，宿主直接访问学习库，不靠 shell 搬迁或技能软链接 |

会话经验仍保存在现有 MemoryStore 中，支持 JSON/SQLite。共享库使用 SQLite WAL 和短事务协调不同进程；相同方法内容去重，改动步骤生成新版本。反馈按会话、worker 和调用 ID 去重，置信度按会话、worker 和宿主 attemptId 的独立执行轮次累计。同轮多次调用或拆分反馈不能刷高置信度；缺少 attemptId 的记录在同会话同 worker 下保守合并。发布方法的原始成功证据不计入后续实践。混合批次的失败反馈仅记录实际失败调用。

共享库 schema 6 为失败反馈增加 superseded：同一方法上，后续独立成功会推翻未结失败，needs-review 随之解除。tool_conclusions 按工具保存当前结论（tool_defect 或 recovered），新会话读取同一库即可避开已确认的缺陷调用，也会在工具恢复后停止拦截。原始失败行仍保留，只是不再计入失败率和家族失败。

宿主额外保存两种 SHA-256 指纹：工具名和参数的请求指纹、工具名和参数及结果的观察指纹。对象字段顺序、调用 ID、worker、会话、执行轮次均不能改变指纹；指纹本身不包含原始参数和输出。置信度同时要求新请求和新观察，重复同一请求即使输出计时等字段改变也不加分。去重覆盖整个共享库及同一方法家族的所有版本，改名或改变 trigger 不能给同一证据重复加分；发布方法的原始证据也不能转借给另一方法刷分。在 SQLite 写事务内领取证据，拒绝反馈时回滚全部领取，避免多进程同时刷分或错误吞掉有效证据。不同工具的调用不能评价该方法。工具统计保留原始成功/失败次数，但以 distinctPracticeAttempts 和 novelObservations 判断是否缺乏独立实践；原始成功率不代表正确率。

方法家族由规范化后的 title 和 trigger 标识，步骤变更产生独立版本并记录 parentId。发布修正版要求新的宿主成功观察或同工具的失败诊断证据；纯改写并复用旧证据会被拒绝。失败后恢复允许保存失败引用 failureEvidence，但必须在宿主记录顺序中存在该失败之后、同一 worker 同一工具的成功执行，不能用失败前的成功证明恢复。新版本显示 familyFailures 和 needsValidation，既不继承旧版置信度，也不删除旧版失败。历史失败仍保留在家族中供下一轮反思使用。

基础自动学习按 title/trigger 精确读取方法家族，不依赖普通召回的前 32 名。宿主固定的超时、缺失资源、权限和参数检查条件一旦从失败中学到，后续窗口移出该失败或切换会话时仍保留；只有这些已知检查句能被基础规则继承，任意模型文本不会自动成为执行策略。后续独立成功只评价保留检查条件的对应版本，不会退回旧基线或替旧失败版本加分。宿主方法查询通过 knowledgeSnapshot 只复制方法列表，跳过原始工具证据、队列和模型检查点；返回数据与持久状态隔离。

召回额外返回 warnings，独立于普通方法数量限制，每个方法家族保留一条、最多八条相关的失败或未验修正摘要。上下文预算不足时先移除完整方法和工具统计，最后才移除紧凑警示；极小预算仍可能无法容纳任何完整记录，不截断 JSON。警示来自记录状态，不声明修正已经正确，也不代替任务验收。

工具失败按 worker 和请求指纹追踪：另一请求或另一 worker 的成功不会清除该请求的未解决失败。归档时写入 learningClass，优先读结构化结果（exists、reason、cannotSearch、code），不靠事后猜报错文本。只有 tool_defect 进入能力失败率并产生 needs-review。caller_error、env_prereq、env_timing 和 unknown 不把工具标成要警惕；软返回的缺失路径也不算成功。相同参数的 caller_error 或 tool_defect 会被宿主直接拦住；缺失路径允许再确认一次，第三次相同调用不再执行。参数变了才放行。显式 probe，以及同一 worker 连续至少 3 次、跨至少 2 个工具的 caller_error，不进入能力统计。没有引用原始输出的工具行为结论是 inferred，不会注入上下文。

默认最多 128 条本地方法、512 条共享方法，每批处理最多 32 条持久化任务，每轮注入最多 6000 字符。32 是批次大小，不再丢弃超过这个数量的积压。共享库容量满时报告后台错误，保留原始执行证据。基础方法状态 `practiced` 要求至少两轮新颖成功观察且来自至少两个宿主会话，仅表示工具实践，不是方法正确性认证；失败保持 `needs-review`，直到同一方法出现后续独立成功，那时失败被标为 superseded，结论改为 recovered 并写入跨会话库。新建大量会话、生成不同输入或改名本身不能证明方法有效，当前机制仍无法自动证明语义方法确实被使用；模型反思属于有证据约束的经验迭代，不训练模型权重。前台学习策略要求逐项核对用户验收条件，披露尚未解决的缺口；任务完成仍须依赖现有宿主证据验收。

## 配置

```js
const runtime = await createInternalTools({
  sessionId: 'session-1',
  memoryFile: './memory.json',
  // 不需要在 allowedTools 中加入学习工具。
  allowedTools: ['todo', 'note'],
  knowledge: {
    libraryFile: 'C:/Users/Administrator/.ubovm/learning/knowledge.sqlite',
    maxLessons: 128,
    maxSharedLessons: 512,
    maxContextChars: 6000,
    maxPending: 32,
    maxReflections: 2,
    reflectionTimeoutMs: 15000,
    reflectionIntervalMs: 30000,
    maxAttempts: 3,
    retryBaseMs: 1000
  }
});
```

- 桌面自动配置用户库和 `reflection: true`，会话宿主使用现有模型客户端创建反思器。SDK 不隐式打开用户目录；可通过 `reflect` 注入宿主反思回调，或在 `createHarness` / `runCollaboration` 配置 `reflection: true`。
- `knowledge: false` 关闭学习；`background: false` 关闭自动处理；`libraryFile: false` 仅保留会话学习；`reflection: false` 保留基础自动学习而关闭桌面模型反思。
- 正常会话内的后台模型默认每 30 秒最多 2 次、每次最多 1200 输出 token、15 秒超时，不占用前台工具调用。预算用尽的任务保留待处理状态，窗口恢复后继续。
- 退出时停止领取新任务、取消未完成模型调用，把执行中的任务恢复成 pending。已经返回的反思结果在应用到知识库之前持久化；重启后可直接落库，无需重复模型请求。来不及执行的任务留在原会话 MemoryStore 中，JSON/SQLite 都可恢复。
- 失败次数和下次重试时间持久化，默认最多 3 次指数退避重试（最多间隔 60 秒）；主动退出不消耗重试次数。达到上限后保留 failed 状态及证据，不无限重试。
- 格式错误、不可用或变更的证据、无新证据的修正、知识容量耗尽属于确定性校验失败，直接保留 failed 及 errorCode，不再进行计时重试。普通模型请求/存储异常继续执行上述有限退避。错误码随状态持久化及 knowledge.failed 事件上报，不保存原始错误中可能包含的秘密。
- 新模型结果和重启恢复后的已保存结果共用同一严格校验：禁止额外字段、错误类型、空证据列表、失败调用冒充成功、窗口之外的引用，以及没有失败后成功记录的恢复声明。全部候选通过校验之后才保存模型结果或修改本地方法；无效检查点不触发再次调用模型。
- 学习错误通过 `knowledge.*` 事件单独上报；共享库不可用时继续本地学习，不阻断用户任务。`learningStatus()` 可读取进度，`flushLearning()` 用于宿主/测试等待，不要求用户调用。
- 模型反思可读取当前模型已授权处理的执行观察。提示要求去除秘密和项目私有数据；被标为通用的方法自动发布，方法内容仍属低信任数据，不能当成已认证能力。

## 技能发现与生效

内置技能源码在 `../skills/self-learning/SKILL.md`，新版应用启动通过 `installBundledSkills` 安装到 `~/.ubovm/skills/self-learning`，不覆盖已有同名用户技能。Skills middleware 创建时扫描，已经开始的一轮不会热扫描；下一次运行时可发现，不必断言只能新建会话。

学习库独立于技能扫描，其他运行时保存的方法在下一次上下文读取时可见。当前修改由源码和临时目录测试验证，实际运行中的旧应用需要重新构建/启动才能使用新版宿主。

## 启动后恢复

应用首屏完成后自动启动 `startLocalLearningRecovery`，无需发送新消息。共享库记录会话 SQLite 路径和 sessionId，不记录模型凭据；升级时也会在应用提供的 harness 存储根目录内发现旧版 `assist.sqlite` / `harness.sqlite`，跳过符号链接。

启动恢复目前为**纯本地模式**：完成基础学习和已经保存的模型结果落库，不创建模型客户端，不发送历史数据，不重放原任务工具。尚未执行的模型反思任务继续保存在队列中，可在原会话正常开启并配置反思器后续行；启动时自动调用外部模型尚未启用。

恢复器每轮默认检查 8 个会话，30 秒后继续扫描。活跃会话的数据库租约不会被抢占；前台 start/restore/resume 前会暂停本地恢复，等待释放租约。退出时恢复服务先停止，再关闭前台宿主。

任务的完整证据窗口固定为当时同一 worker 的最多 8 条记录，恢复时校验调用 ID 和 digest；不会拿后来出现的证据重新解释旧任务。completed 任务保持幂等；running 任务在重新取得会话租约后恢复为 pending。模型结果保存但未落库的任务可以离线完成，已结束任务不重复处理。

后台调度和状态查询只读取任务 ID、类型、状态、重试时间及模型结果是否已保存，不复制整个 MemoryStore、证据正文或模型候选内容。执行任务时按 worker 和调用 ID 读取其引用的证据，再校验 digest；返回数据与存储隔离，调用方修改不会污染持久状态。

测试：`node --test src/harness/learning/test/*.test.mjs`，包含真实杀死子进程后恢复、75 条积压、反思结果检查点、预算延期、退避持久化、旧库迁移及离线启动恢复。
