# Agent 后端运行时

这里负责 Agent 执行、恢复、状态投影和执行记录持久化。模块可随 Harness SDK 单独打包，不依赖 IDE、VS Code 或浏览器页面。

调用方向：`IDE 页面 → 扩展宿主 agent-service → Worker 后端`。宿主向后端提供配置读取、审批、回复保存和编辑器工具等能力；后端通过反向 RPC 调用。只有宿主可以访问 VS Code API，页面只能发送交互请求和渲染数据。

消息约定：

- `request { id, method, args }` 与 `response { id, value | error }` 成对；双向请求分别分配 ID。
- `abort { id, error }` 传递取消信号，仍等待工具完成清理，避免编辑尚未结束就启动下一次执行。
- 开始、恢复、删除等命令响应包含 `result` 和 `snapshot`。快照由会话 ID、递增版本、执行状态及摘要组成。
- 业务命令被拒绝时，响应包含 `failure` 和可用的最新 `snapshot`，宿主先更新状态再抛出错误。这样检查点已恢复但开始被拒绝时，IDE 仍能显示正确的“继续执行”状态；RPC 协议/传输错误仍走传输层错误响应。
- 流式 `snapshot` 使用确认机制，逻辑队列最多一条在途，超时后仍未结束的实际发送最多四条；其余更新仅保存会话 ID，按顺序读取最新状态。IDE 丢弃低版本及旧线程的消息。
- 命令响应替换流式快照或会话被删除后，旧发送任务及其重试失效；失效任务稍后失败也不会再发布错误覆盖新状态。
- 取消旧快照会立即结束逻辑等待并清除超时计时器，其他会话无需等待旧发送响应；旧传输真正结束前仍占用物理发送容量，重复取消不能绕过上限。投影回调中删除会话或关闭队列后，不再创建发送和超时任务。
- 快照发送、超时和取消共用幂等完成入口，避免每条快照建立多层 Promise 竞争与清理链；逻辑完成与物理传输释放仍分离。持续发送按批次及时间预算让出事件循环，测试等待实际完成条件，不假定一次事件循环即可完成发送。
- 快照发送明确返回 `false` 视为未送达；抛出或拒绝 `undefined`、`null`、`false` 等值仍按失败处理。错误安全归一化后上报，失败快照的重试有效性立即撤销；错误不会自动重放命令或导致坏快照无限重试。
- 回复保存、审批和工具执行属于可靠请求，不进入可合并的状态队列。
- 普通待响应请求和执行中请求各限制为 256 条；`cancel` 另外预留各方向 8 条容量，`close` 独享各方向 1 条容量。普通请求和停止队列满载均不会挤占关闭。重复停止点击按会话合并，停止容量暂满时等待重试。
- `interruptCommand` 与 `cancel` 共用控制请求预留容量；按会话和随机命令 ID 合并重复请求。宿主注册的活动命令句柄绑定到当前执行，旧卡片、其他会话和已结束命令不能中断新的调用。单命令中断保留整轮任务的运行状态与已有输出，时间线显示“已停止”；主对话、内嵌和原生 Worker 日志均支持。
- `backgroundCommand`（“放在一边”）释放当前命令的工具等待，让 agent 继续处理其他工作；命令卡片保留后台运行状态、实时输出和中断入口。宿主句柄持续到进程真正结束，工具返回不代表命令成功。本地与 SSH 命令均由宿主持有：`retain=true`、常见长跑命令自动识别，或用户放在一边后，agent 本轮结束或“停止执行”不会打断该任务；进程仍存活时即使本轮已结束也可放在一边。跨轮保留实时输出和中断入口；驻留后取消前台执行超时，输出采用有界滚动日志而不因日志达到上限停止服务；命名会话上的驻留命令会释放队列并让后续调用启用新 shell。每个会话最多同时驻留 32 个任务，限制依据活动进程句柄而非界面投影；保留最近 32 个结束任务日志。任务保留排队、启动和停止阶段，停止标记不被后续日志覆盖。进程清理未确认或延迟 shell 关闭失败时标为失败，并通过宿主清理屏障报告错误。切换工作空间、删除或替换会话、退出应用时会终止并等待清理。日志按有界数据块保留，刷新不重拷贝完整窗口。驻留状态和日志独立落盘，运行日志最多每秒写入一次，结束及关闭时等待落盘；损坏或超过 4 MiB 的驻留历史独立报告错误，保留原文件，不阻塞会话，修复后可重试恢复。应用重启后只恢复日志，遗留运行记录标为已停止，不自动重启进程；SSH 驻留依赖当前应用内仍存活的连接，重启后同样不会恢复远端进程句柄。
- 对话输入框上方的“后台任务”栏聚合主 Agent 和 Worker 的后台命令；探索模式在工作区底部显示。默认折叠显示运行数量和最新一行输出，展开后按命令查看状态、耗时、所属 Agent 和实时日志。停止操作仅针对选中的命令；完成、失败及停止结果保留到用户点击“清除已结束”。任务列表与清除状态按会话隔离，断线时明确显示状态待确认。
- 宿主收到快照后只冻结一次，后续读取复用只读对象；命令返回状态与快照共享传输对象，避免复制两份时间线。恢复失败等 IDE 提示仅覆盖展示数据，不修改后端状态。

线程崩溃会关闭 RPC、取消宿主请求并释放工具引用。下一次恢复或启动由宿主创建新线程，任务不会自动重跑。重建前等待旧线程退出；关闭服务后拒绝新命令。

宿主每 5 秒发送独立的 `ping/pong` 心跳，不占用业务请求容量；探测发出后 20 秒未收到对应响应，关闭 RPC 并终止失联线程，活动任务标记为 `AGENT_HEARTBEAT_TIMEOUT`。宿主自身长时间暂停或系统休眠后先重新探测，不直接判定后端崩溃。正常异步长任务仍可响应心跳。

主页面通过 `connectionProbe/connectionStatus` 每 5 秒检测扩展宿主，并读取 Agent 连接状态。连续 20 秒无响应时显示断线提示，将正在执行的状态标为待确认，保留草稿并阻止发送操作。后台页面暂停检测，重新可见后重新探测；迟到或不匹配的响应不会清除断线状态。恢复通信只请求最新页面状态，不重放任务。未启动 Agent 的空闲状态属于正常连接。

宿主只保留成功提交的会话 ID、模式和目标描述，不缓存完整输入、上下文或凭据用于重跑。目标运行崩溃后显示可恢复；用户显式点击继续时，若新线程尚未加载该会话，先恢复检查点再调用继续。工作空间归属仍由后端重新校验，检查点无效或属于另一工作空间时拒绝执行。恢复期间的停止会在模型启动前生效。

崩溃时使用 `interruptExecution` 结束宿主缓存中的活动标记：未完成的 Worker、工具和活动变为中断，运行摘要的活动 Worker 数归零，部分输出保留。已完成 Worker 的结果和此前发布的只读快照不会被修改；此操作只更新显示缓存，不替代后端检查点恢复。

RPC 断开与宿主工具结束分别跟踪。旧线程退出后，如果宿主工具仍在完成写入或取消清理，重建返回 `AGENT_HOST_CLEANUP_PENDING`，待清理结束后可重试，避免新旧执行重叠。关闭服务的 10 秒期限同时涵盖后端关闭和宿主处理器清理。SDK 取消、保存或关闭失败会被收集，其他会话仍会清理，最后统一返回关闭错误。

RPC 在调用处理器之前登记其完成屏障。处理器同步触发断连或关闭时，`isIdle` 和 `drain` 仍包含当前任务，直到它完成清理，避免重入关闭误判后端已空闲。

错误隔离：`errors.cjs` 将任意抛出值转为有长度限制的普通错误字段，避免 getter、转换函数或不可克隆字段让错误报告再次失败。畸形请求/响应返回 `RPC_PROTOCOL_ERROR`；单个处理器、结果序列化或异步通知回调失败不会升级为未处理的 Promise 拒绝。执行清理有最后一道会话级异常边界，定时持久化同时捕获同步抛错和异步拒绝。

单个快照投影/推送失败会通过带版本号的 `snapshotFailure` 返回该会话的错误及运行摘要，保留上一次可用时间线与停止能力；其他会话继续发送，下一次更新可恢复正常快照。这里不会主动抛出异常终止后端线程。真实端口断连仍会关闭 RPC 并清理待处理请求。

SDK 事件回调也有独立错误边界，包括由定时器或其他异步来源触发的回调。事件处理失败会记录 `AGENT_EVENT_ERROR`，中止当前运行的信号，并等待原执行流程完成工具清理和持久化；不会抛出未捕获异常终止共享线程，也不会将失败运行误报为正常取消或成功。后续运行会清除该错误标记，已完成的其他会话保持不变。

IDE 的状态发布按视图代次隔离。完整状态与增量共用合并队列，视图重建使旧代次失效并释放逻辑发送名额，旧桥接迟到的完成或失败不能释放新请求的名额或覆盖新错误。超时后的底层发送仍计入实际在途数量，每代最多 4 个；容量释放后补发最新状态。快照读取、可见性检查及错误观察器的异常均被限制在本次发布中，不影响后续调度。

Worker 展示记录先选取最近 100 个 Worker 再投影、脱敏和计算大小，整个文件严格限制在 8 MiB 内。每个 Worker 优先保留最近 500 个时间线片段，空间不足时继续裁剪旧片段；`omittedWorkers`、`omittedParts` 记录省略量，恢复后再次关闭不会丢失这些计数。每个片段只计量一次，避免逐条删除后反复序列化整个记录。清空列表也写入空记录，避免重启后恢复已清除的 Worker。这些限制仅作用于展示缓存，不改动执行检查点和工具证据。

持久化队列仍只保留一个正在执行的写入和一个最新待写入状态，所有等待者共享完成屏障。任何抛出值（包括 `null`、`undefined` 和其他假值）都会使屏障拒绝；其余待写入状态仍会尝试保存，下一轮可以重试。协助模式不在会话条目中额外缓存整轮输入和消息历史；目标模式只保留继续执行所需的输入。

连续补充任务的写入队列和 IDE 组件发布队列使用协作式循环检查点：每批最多 256 次检查，或单调时钟显示已运行 8 毫秒时，通过 `setImmediate` 让出事件循环。普通检查不创建 Promise，计数器按批重置；每个活动队列仍只保留在途任务和最新待处理状态。让出后重新检查组件代次，销毁或切换后的旧任务不能恢复发布。时间片不能抢占单个同步阻塞回调，也不是硬实时响应保证。

运行 `node --expose-gc src/renderer/test/integration/stress/long-run-stress.cjs` 可复测同步发布、异步发布和写入调度，每组默认一千万次；可用 `UBOVM_LONG_RUN_ITERATIONS` 调整次数。测试检查计数完整性、心跳推进和 GC 后保留堆内存，并报告耗时与采样峰值。回调为空操作，不代表一千万次真实磁盘写入、模型调用或跨天运行验证。

会话关闭时，各服务关闭、取消订阅、租约释放和数据库关闭分别收集错误，单个同步异常或异步拒绝不会跳过其余清理。关闭完成后释放会话目录归属，所有关闭调用者共享同一个完成屏障；有清理错误时统一返回 `AggregateError`。本地命令输出观察器的同步异常和异步拒绝均被隔离，不改变子进程执行结果。

初始化失败同样逐项清理已创建的服务、租约和数据库，数据库关闭报错也不会留下进程内目录占用。清理成功时保留原始异常；清理失败时将原始异常设为 `AggregateError.cause`，并与清理异常一起收集。内部工具先等待活动调用和后台学习结束，再分别尝试刷新内存、关闭自有浏览器和 SSH，最后关闭学习库；同步抛错与异步拒绝均不会跳过后续步骤。

JSON 快照写入在首次异步文件操作之前固定序列化内容，调用方随后修改对象不会改变正在写入的快照。序列化失败不创建目录或临时文件，旧快照保持完整；有效内容仍经过临时文件写入、同步和重命名后替换旧文件。

SSH 命令输出按 16 毫秒或累计 32 KiB 的阈值合并上报，减少小包引发的状态投影和线程通知；保留 stdout/stderr 各自的 UTF-8 解码器及到达顺序，完成、取消和失败前同步刷新缓冲。输出总字节上限保持生效。观察器同步异常和异步拒绝不会中断命令；停止原因先于通道关闭记录，避免同步 close 事件将取消或超限误报成功。stderr 错误进入命令失败路径，迟到通道会关闭并吸收后续错误。
## Stability boundaries

Snapshot publication uses a five-second delivery deadline and at most four unresolved physical sends. A timeout releases the logical queue so another session can publish, invalidates that send's retry predicate, and reports the affected projection without replaying task commands. At capacity, updates retain only session IDs; release of an old send resumes publication from current state. Closing stops timers and prevents further reads or sends.

RPC payloads reserve request capacity during structured cloning and receive their sequence ID afterward. This keeps getter-triggered nested calls ordered on the wire and prevents reentrant capacity overruns. Completed request IDs cannot execute again; protocol replay closes the local connection. Active tool cleanup remains represented by the separate drain barrier.
