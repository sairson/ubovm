# UBOVM Core

## 组件就绪与异步回调

首屏绘制和会话加载完成使用独立通知。加载完成通知绑定实际提交的状态快照、页面生命周期和渲染代次，并等待两帧绘制；等待期间收到新状态会重新等待最新提交。执行记录恢复结束前不解锁侧栏。组件失败时仍显示可操作的恢复界面，避免把重试入口困在加载遮罩后。

异步通知发送失败或返回 `false` 时，保留待确认状态，由后续渲染或可见性恢复触发重试，不在每帧自动循环。页面暂停会解除旧通知对新通知的占用，旧回调不能清除新一代的待确认状态。扩展宿主忽略其他会话的完成通知。

异步桥接返回的 Promise 最多等待 5 秒；超时会释放通知占用和计时器，并显示同步或重新加载入口。暂停、隐藏页面或打开设置会主动取消等待；已取消或超时请求的迟到成功、失败均被消费，不再影响新页面。原生桥接的同步发送不创建超时计时器。此期限针对通知发送，不取消后台任务，也不会自动重复提交操作。

首次状态请求发送失败会重新显示加载重试按钮。已恢复页面或旧生命周期中的失败回调不会重新显示过期错误。回答流式更新时，完成的工具卡片及工具组只在属性变化时写入 DOM，避免重复触发观察器和样式计算。

## 后台恢复的页面重新加载期限

页面重新加载的 15 秒等待期限在实际可见性切换或 `pagehide` / `pageshow` 恢复后重新计时，避免把后台停留时间误报为加载失败。重复可见性通知和重复 `pageshow` 不推迟期限、不创建第二个计时器，也不重放加载或任务请求。草稿仍先保存再发送重新加载请求；持续可见但没有完成的加载仍会超时并恢复重试按钮。此修复针对恢复提示的期限，不代表已定位整窗白屏的根因。

恢复看门狗在页面隐藏或 `pagehide` 时释放 5 秒轮询计时器，前台恢复时只建立一个计时器。页面仍隐藏时的 `pageshow` 不启动轮询；已退出页面的可见性通知不能重新创建计时器。这样减少后台页面的无效唤醒，保留前台加载失败的检测能力。

系统时间回拨时，看门狗重新建立加载、更新和重新加载的 15 秒期限，避免恢复入口等待旧系统时间而长时间保持不可用。回拨不重放请求；回归测试分别覆盖三个等待阶段，并验证重新加载按钮重新开放。该验证使用虚拟时钟，不代表白屏根因已解决。

## 中断后保留历史

停止协助模式只取消当前执行，不清空已有对话。中断或失败时，已生成的回复、思考展示与工具记录会保存到对话历史；工具的未完成状态保持为中断。历史先写入执行目录的恢复记录，再投递到会话，保存失败时阻止下一轮覆盖并允许重试；恢复不重新调用模型或执行工具，消息 ID 用于避免重复添加。

模型侧同样保存被中断的这一轮及已经接受的引导。下一轮保留已完成的工具结果，为缺少结果的调用补充明确的“结果未知”记录，要求核实后再决定是否重试。正常历史容量上限仍生效；此改动不能自动找回此前已经被覆盖且未保存的临时输出。

## 队列输入引导

协助模式运行期间，每条待发送输入提供“引导”按钮。点击后，该输入及入队时捕获的编辑器上下文交给当前主 Agent，在模型回复或工具调用后的执行边界调整后续工作；输入从队列移除并保留在用户消息历史中，不再另起一轮执行。其他输入仍按原队列调度，输入框草稿不受影响。主 Agent 根据新方向决定后续协作安排，已派发 Worker 不会被直接注入或自动取消。

引导按钮只在主 Agent 就绪时可用，请求绑定当时的运行 ID；过期点击不能影响下一轮任务。同一输入标识的重复请求只注入一次，不同内容复用标识会被拒绝。每轮最多接受 100 条引导。引导沿用当前任务的工具审批设置，不修改审批权限。

引导输入在对话历史中使用独立标记、浅色卡片和侧边线，与普通提问区分。卡片显示等待送达确认、已送达或送达待确认；已送达只表示 Agent 接受输入，不代表任务已完成或模型已执行新方向。标记随历史保存，重启后未完成的发送显示待确认。状态更新保留正文节点；队列刷新保留滚动位置和操作焦点，按钮暂时禁用时焦点留在对应行，操作结束后恢复。

队列按输入 ID 复用消息行，状态刷新不清除正文选区；切换会话重置队列滚动位置，不把旧会话焦点带入新会话。最后一条移除后焦点返回输入框。未确认的引导在卡片旁显示核实提示，对话导航条也标注“引导”，便于定位；窄屏下提示自动换行。

点击队列正文或键盘聚焦后按 Enter 可查看完整输入。预览保留换行和原始文本，支持选择复制与滚动阅读；Esc 关闭后返回原队列消息。输入出队或切换会话自动关闭并清除预览内容，已有草稿保持不变。预览仅展示文本，不执行 HTML 或脚本。

停止、回退、恢复队列及队列修改等待确认时，共用操作锁，立即禁用会改变队列的按钮，全文预览仍可阅读。点击时再次检查会话、按钮是否仍在页面、操作锁及运行 ID；旧按钮回调与连续双击不会再发出请求。失败确认后恢复可用操作；加载提示区分发送引导、更新队列和继续队列。

历史消息的回退按钮也使用同一操作锁：引导发送、队列修改、停止及恢复期间不能同时裁剪历史。回退回调绑定当前会话与当前渲染内容，消息删除、内容替换或会话切换后失效；失败回执保留草稿，成功回执将取回原文与等待期间的新草稿合并。

宿主收到回退请求时，在设置停止标记前校验目标确为现存用户消息；串行等待结束后再次校验，避免迟到或重复请求停止无关运行。无效标识与助手消息不能触发回退，旧版用户消息生成的标识仍兼容。

流式渲染中的按钮、输入区、执行状态及目标面板属性仅在值变化时写入，避免重复设置 `hidden`、`disabled`、文本与无障碍属性。执行状态刷新不再同步测量输入框；文字输入、容器尺寸变化及显式草稿恢复仍负责重新计算高度。`render-performance.mjs` 的 12 次流式刷新场景中，输入区重复 DOM 更新由 156 次降至 0 次，宽度读取由 12 次降至 0 次；这是局部工作量计数，不代表整机帧率。对话导航短线采用固定宽度与 `transform` 缩放，避免宽度动画触发布局，保留减少动态效果设置。

工具时间线同样跳过未变化的中断按钮属性与后台步骤分组状态；80 张已完成工具卡片、30 次正文更新的回归场景，卡片重复属性写入从 4,800 次降至 0，原卡片节点仍保留。对话骨架收到相同历史数组时不再额外申请位置测量帧，滚动、尺寸变化、历史变更和页面恢复继续触发同步。

已发布回复的文件修改摘要按历史、宿主摘要快照和忙碌状态失效。纯执行流更新复用这两份不可变数据时，跳过历史摘要组件调用及文件列表序列化；新摘要、历史更新和执行结束仍同步刷新，确保撤销按钮状态正确。组件全部更新成功后才记录摘要快照，失败仍可重试。性能回归覆盖 20 条历史回复和 12 次流更新，以及随后新增文件摘要与执行完成。

所有工具卡片（包括文件、搜索与 MCP）在折叠时仅保存最新详情数据，不改写隐藏输出、参数或统计输出行数；摘要状态、耗时与中断操作照常更新。展开后渲染最新详情，已展开卡片仍保留增量输出和阅读位置。`tool-cards.mjs` 对命令、文件、搜索和 MCP 分别执行 1,000 次折叠输出更新，验证隐藏详情零 DOM 更新并在展开后显示最后一次结果。

展开日志追加输出时，参数文本按成功渲染的值缓存，避免反复读取未变化的大段 DOM 文本；工具栏及截断提示的显示属性也仅在变化时写入。回归测试使用 64,000 字符命令参数与 50 次日志追加，检查参数零重复读取、工具栏零重复属性写入，并验证后续参数变化及时显示。

后端启动与恢复请求在入口处执行独立结构化复制，早于启动通知和异步工作区准备，调用方后续修改不会改变执行内容或会话归属。不可传输的数据在获取会话锁、启动 Worker 或设置忙碌状态之前拒绝；失败后仍可提交正常请求。`threaded-harness.cjs` 覆盖同步观察者修改、准备期间修改、恢复归属和复制失败后的可用性；传输与界面回归另覆盖心跳超时、容量满载、崩溃清理、旧状态与断连草稿保护。

连接心跳发现超过超时阈值的计时中断或系统时间回拨时，即使页面没有收到可见性事件，也会进入重新连接状态。新的探测确认后重新请求完整界面快照，休眠前的迟到回复不能完成恢复；该过程不重放用户任务。此恢复针对仍存活的页面，不替代渲染进程崩溃诊断。

前端与 Worker RPC 心跳还区分本地调度延迟和远端失联：相邻计时回调间隔超过两个探测周期（上限为超时阈值）时废弃旧探测并重新确认，避免本地阻塞期间排队的回复引发误断连。正常周期下持续无回应仍触发超时，旧探测回复不能确认新连接。前端心跳参数必须是合法正整数计时值，超时必须大于周期，校验失败不会安装监听器或定时器。

重复的页面可见性通知不再重置探测和超时起点；只有真实前后台切换才重新同步，页面恢复时也不重复安装心跳定时器。发送接口明确返回 `false` 或异步拒绝时及时判定发送失败，过期探测的迟到失败不能覆盖新连接。回归覆盖连续重复通知、正常超时、单一定时器、隐藏暂停、恢复与销毁清理。

发送前将队列预留状态和用户历史原子保存。明确拒绝时原位恢复输入，并移除本次临时历史；通信异常或确认落盘失败时完整保留输入及附件，显示“送达待确认”，禁止继续队列或再次引导该条。重启后未完成发送也转为待确认，用户核实后可取回编辑或删除。不会在通信异常后自动重放。

同一执行边界前到达的多条引导按顺序合并交给下一次模型调用，避免逐条推进时忽略较新的修正。主 Agent 自动等待 Worker 完成时，引导可以提前唤醒主 Agent 调整后续安排；正在执行的模型请求、工具批次和显式等待工具仍在各自边界后处理，不中止已开始的操作。

宿主在异步通信前固定输入快照，调用方随后修改文本或附件不会改变已提交请求。发送预留落盘期间发生停止或关闭时不再注入。后端明确确认未发送的校验／容量拒绝会恢复普通队列；SDK 注入异常和通信异常仍按送达不确定处理。SDK 本身同样限制每轮 100 条引导，并在注销回调之前使旧句柄失效；注销通知失败仍执行取消与监听器清理，上下文序列化期间取消也不会追加新指令。

## 稳定性维护

页面渲染帧携带取消代次，页面暂停或切换后迟到的旧帧不能修改新调度槽。加载遮罩、页面切换、入场动画和连接状态的收尾分别隔离；收尾异常保留恢复入口，全部成功后才清除恢复提示。宿主状态发布器在安装计时工作前检查延迟和回调配置，避免无效计时值被系统压成高频循环。

恢复按钮处理同步发送失败、明确返回 `false` 和异步拒绝；旧发送或旧页面代次的迟到失败不能覆盖新恢复状态。重载前直接调用同步草稿保存接口，监听器异常不能绕过保存确认；连续点击只发送一次重载，15 秒无结果时重新开放恢复入口。重复可见性通知不延长渲染检测期限。完整状态与执行增量在消耗版本号之前检查对象、列表和模式结构，异常新快照保留当前页面，过期快照直接忽略。

消息释放在调用 Markdown 等依赖之前退役所属视图，并逐项尝试剩余卡片与嵌套资源清理；单个依赖报错不保留后续时长计时器或旧操作句柄。计时更新异常也只退出损坏卡片。超长纯文本使用 MutationObserver 验证缓存完整性，被外部同步或异步替换后可用相同快照修复，退出纯文本模式或释放时断开观察器。

页面脚本分别使用带 nonce 的独立脚本块加载。`runtime-guard.js` 在业务依赖之前取得唯一的 VS Code API，提供独立恢复提示；后续依赖语法错误、未处理异常、启动或可见页面更新超过 15 秒未完成时仍可同步状态或手动重载。后台时间不作为渲染失败依据。恢复只请求界面快照或重建 Webview，不重放任务；重载前同步保存草稿，保存失败时阻止重载。资源组装失败时宿主返回不依赖资源文件的静态恢复页面，并允许修复文件后重新加载。

状态接收异常会恢复版本计数及上一次会话归属，使相同版本的宿主快照仍可重新同步。会话切换逐项隔离组件清理失败，页头与正文分别渲染，单个区域异常不能阻止其他区域更新。手动重试会取消滞留的渲染帧。超过 256 Ki 个 UTF-16 字符的 Markdown 使用完整纯文本显示，增量追加复用文本节点，避免为大输出反复构建富文本解析树；恢复到较短内容后重新使用正常 Markdown。以上兜底适用于仍可执行 JavaScript 的 Webview，整窗渲染进程崩溃或彻底阻塞仍由 Code OSS 的原生故障处理负责。

完整页面状态和执行增量共用宿主递增的 `viewRevision`。前端分别跟踪完整状态与执行状态的最新版本，重复或过期消息不触发渲染；其他会话的增量不占用当前版本。完整状态迟到时仍可刷新消息历史、审批与上下文，同时保留已经收到的较新执行状态。切换会话后，旧完整状态不能把页面切回去。该机制不重发命令或恢复执行，只约束状态显示顺序。

完整页面状态与执行增量共用合并推送队列，只保留最新待发完整状态和增量标记。发送时读取最新执行信息，完整状态成功交付前保留历史、审批和上下文，旧确认不会清掉并发产生的新状态。发送超时不等于桥接 Promise 结束：每代页面最多保留 4 个实际未完成发送，容量满时继续合并更新；旧发送结束释放容量后自动补发最新状态。页面销毁／重建独立重置容量，旧代次的完成或失败不会干扰新页面。

可用 `node --expose-gc --test src/renderer/test/host/agent/push-long-run.cjs` 运行推送压力测试：一千万轮完整状态与增量混合更新，虚拟推进 16 小时 40 分钟，覆盖持续超时、容量限制、迟到确认、恢复后最新完整内容及堆内存检查。虚拟时间测试不替代真实跨天运行验证。

输入自动调度按会话合并完成通知，每个会话最多保留一个尚未开始的调度任务；调度开始后释放标记，允许执行期间的新完成通知安排下一条输入。追加历史和出队落盘后重新检查关闭状态，关闭期间不再启动排队输入，已经出队但尚未启动的输入会恢复并暂停。审批状态通知隔离同步异常与异步拒绝，界面刷新失败不会改变审批结果或中断宿主。

对话骨架独立于消息正文渲染，初始化、增量更新和异步位置测量失败后可通过“重新显示页面”重试；新增与回退消息保留仍有效的导航节点和键盘焦点。切换会话立即释放旧导航，失效按钮不能影响新会话；页面挂起、后台和设置面板打开时暂停尺寸监听与待执行帧，恢复时只同步当前状态。侧栏运行图标跟踪实际显示状态，首次读取后的结束通知也能恢复普通图标，删除会话和销毁时清理状态缓存。

思考日志按每页最多 120 条渲染，支持较早、较新和最新日志导航；翻页释放离开页面的消息视图和计时器，阅读旧页时追加日志不会改变该页起点。“回到底部”同时返回最新页。历史数据不删除，当前会话快照仍会随实际记录增长；此限制约束渲染节点，不是整个 IDE 的内存硬上限。

切换会话立即清空旧日志、聊天消息和黑板视图；黑板销毁时断开 ResizeObserver、移除页面生命周期监听并取消动画帧。嵌套消息替换、移除和流式消息结束均执行递归释放。大执行快照的推送间隔按条数在默认 75ms 到 500ms 之间调整，桥接层仍只保留一个在途推送和一个待推送标记。

黑板增量增加节点时保留已有节点坐标，只为新增节点分配空位；删除节点会清理坐标缓存。“适应画布”清除手动和自动位置并重新布局。缩放和平移共享同一变换，不参与浏览器滚动和 CSS zoom 布局。

探索图的标签避让使用每帧重建的空间索引，仅检查附近节点和已接受的标签，保持原有 4px 间距与显示顺序；超大矩形采用有界回退，避免网格分配失控。缩放低于 65% 时跳过标签几何测量，隐藏标签的意图连线仍可通过键盘访问。布局读取集中完成后再更新可见性，减少交错读写带来的重复布局。

探索图按来源、目标和意图复用 SVG 连线，更新和拖动时保留键盘焦点，删除关系时释放对应节点；纯几何更新跳过事实文本与详情重建。事实卡片标明记录中的已确认、已否定、待补证或受阻状态。页面恢复后重新监听画布尺寸并安排布局，避免恢复后连线与容器尺寸脱节。IDE 宿主使用迭代方式冻结接收的状态快照，避免深层数据递归溢出，并在状态准备完成后再提交版本号。

Worker 日志只缓存最近访问的 8 个渲染视图；淘汰和切换会话时释放消息计时器与节点引用，再次打开时从当前工作记录重建。此限制只影响视图缓存，不删除 Worker 记录。

页面离开时暂停连接探测与 Worker 计时器，恢复后重新启动并确认连接、重新同步状态；重复恢复不会叠加计时器。RPC 在发送前校验取消信号，无效信号不会发送请求或占用停止/关闭通道。

UBOVM 的工作台扩展，使用 VS Code Extension API 与 CommonJS 入口，在独立 Worker 线程中加载应用内打包的 ESM Harness SDK；扩展宿主管理编辑器与面板，Webview 负责界面与消息通信。

`host/agent/agent-service.cjs` 是 IDE 宿主的消息桥接层；真正的 Agent 服务、线程入口、消息协议和状态投影位于后端 `src/harness/ide/runtime/`，不依赖 renderer、Webview 或 VS Code。模型执行、调度与执行记录持久化在后端 Worker 线程完成；宿主只提供配置、凭据、审批和编辑器工具能力。前端 `webview/` 只处理交互与渲染，包括错误提示文案。

状态推送全局最多一条在途快照，其余更新仅按会话 ID 合并，发送时才投影最新状态。命令响应携带版本号，旧快照不能覆盖新状态；收到的状态只冻结一次，界面读取复用只读快照。普通 RPC 的待响应请求与执行中请求各限制为 256 条，停止另有各方向 8 条容量，关闭独享各方向 1 条容量。单个快照失败只报告该会话错误，保留上次可用内容及停止能力。线程按需启动，崩溃后由下一次恢复或启动操作重建，不自动重跑任务；已完成会话不受其他任务崩溃影响。启动期间会话立即占用，停止请求不会因线程尚未就绪而丢失。关闭先保存记录，超过 10 秒则终止线程。

协助和探索会话未选择目录时，自动在 `~/.ubovm/workspace/<会话ID>/` 创建独立工作空间（旧会话的非 UUID 标识使用稳定哈希作为目录名），并持久化保存路径。顶部工作空间按钮显示完整路径，可点击选择其他本地目录；已配置的历史会话保留原目录。切换会话后，文件读写、搜索、验证与 Agent 本地命令使用该会话的目录。运行中不可切换工作空间；停止后可切换，执行检查点按工作空间隔离，切回原目录仍可恢复原执行。

## 目录与职责

协助模式的对话右侧提供紧凑的对话骨架，每条短线对应一轮已发送的用户消息。悬停、键盘聚焦或点击展开按钮可查看轮次与提问摘要，点击条目跳转到原消息；当前阅读轮次随滚动高亮。骨架随历史回退和会话切换更新，排队输入不计入历史，浏览旧消息时流式回复不会强制滚回底部。

协助会话支持输入队列：Agent 运行时按 Enter 或点击“加入队列”，后续输入按顺序执行；队列最多 20 条，每条保留提交时的上下文和审批模式。可以删除待发送输入或取回编辑。停止、执行失败或重启后，队列需手动继续。用户消息上的“回退”会先等待 Agent 停止，再移除该消息及后续对话、将原文放回草稿，并隔离旧执行上下文；已有草稿会保留。回退不会撤销文件修改、命令或其他外部操作。

系统配置的模型页支持命名保存多套模型配置，在默认模型、思考 Agent、执行 Agent 和摘要模型之间复用；选择后点击“保存更改”应用到当前角色。可另存副本、重命名或删除已保存配置，删除不会影响角色现用模型。同一服务商和 API 地址共用凭据，API Key 仅保存在系统凭据库。旧的单模型设置可继续使用。

首次打开时，默认模型或默认 SSH 连接尚未有效配置，会自动显示初始化页面；此时打开系统配置也会进入引导。依次保存模型、SSH 后，可以配置浏览器与搜索，也可以直接完成初始化。各步骤复用系统配置的校验、凭据存储、SSH 连接测试和未保存更改保护。完成状态根据实际已保存的模型和默认 SSH 配置计算，不额外保存“已完成”标记；中途退出后下次启动继续，已有完整配置的用户直接进入工作区。配置有效不代表网络连接测试通过，API Key 按服务商要求填写，支持无需 Key 的自托管模型。

初始化页面重新加载后仍会检查未完成项，并避让正在进行的显式设置导航。首次 SSH 步骤直接提供连接表单；保存后前往尚未完成的基础步骤，已有配置未修改时可直接继续。完成前重新读取宿主配置，外部变更导致缺项时返回对应步骤；读取失败保留页面供重试。设置请求与 SSH 测试使用每代页面独立的请求编号，旧页面迟到的结果不会覆盖新页面或错误结束初始化。初始化与普通设置分别缓存表单，未保存输入需明确保留或放弃。

配置快照先校验必要分组与初始化状态的一致性，再替换当前数据；无效切换不会改变已有表单的提交分组。读取失败和渲染失败分别处理：渲染失败保留可用控件并暂停编辑与提交，可用“重新显示当前步骤”在本地恢复，无需重新读取配置；重新载入仍可获取新配置。放弃的草稿在读取失败后不会残留为“未修改”表单。初始化只创建需要的连接表单，不创建隐藏的模型库和协作说明，但保存时保留已有模型配置身份。相同快照复用控件与焦点，不重复改写标题，也不修改收到的快照。`node --test src/renderer/test/integration/webview/initialization-stability.mjs` 覆盖损坏快照、连续渲染失败、本地恢复、超时、无效导航及 100 次重复刷新。

SSH 页可添加、复制、删除多个连接并选择默认连接；复制仅复制连接参数，密码和私钥口令需重新填写。各连接可独立测试。终端下拉菜单可选择任一已保存 SSH 主机，默认连接用于新建默认 SSH 终端。

## 界面与执行

- 扩展标识：`ubovm.ubovm-core`
- 扩展宿主入口：`extension.cjs`；主空间对话：`webview/index.html`；原生启动画面：`workbench/startup.html`。
- 从左到右为会话列表、主对话、文件查看与编辑区、项目文件树。主对话使用 `ubovm.welcome` WebviewPanel，固定在第一个编辑器组；原生标签和标题栏不创建并回收占用高度。打开的文件进入右侧编辑器组，保留文件标签和关闭按钮。
- 右侧原生文件树跟随当前会话的工作空间，切换会话、模式或目录时替换根目录；默认工作空间创建完成后自动展开，空目录显示空文件夹提示。仍可手动展开或收起，右侧文件栏不提供独立选择入口。目录监听、新建文件与空目录判断均使用会话目录。`host/ui/session-explorer.cjs` 串行合并切换请求，`resources/patches/session-workspace.patch` 提供原生 Explorer 桥接，不改变窗口工作区或重启扩展宿主。
- 左侧原生项目与会话树由 `harness/session/sessions.cjs` 提供，容器为 `ubovm-sessions`，视图为 `ubovm.sessions`。它位于 Secondary Side Bar；Primary Side Bar 位于最右侧并显示原生文件树，内置侧栏 Chat 已禁用。点击项目行即切换到该项目（`ubovm.openProject`）；展开后同时列出协助与探索会话，点击另一模式会话会跨模式打开。项目行描述显示目录名与会话数，右键可更改项目目录、重命名或删除。
- 新建项目：侧栏与对话页共用同一居中项目弹窗；在弹窗内输入名称后选择建议目录或浏览目录，目录不存在时在提交时创建。目录已属于保存的项目时直接打开该项目。项目列表当前项目置顶，其余按最近使用排序；切换项目或会话后树会自动展开并定位到当前项。项目行的加号可创建当前模式会话；普通新建会话默认继承当前项目。同一项目下的会话共享目录和文件树，消息及执行状态独立保存。切换项目目录（树菜单、项目切换弹窗或会话顶栏）会同时更新该项目所有会话，项目内有执行中的会话时禁止切换。旧会话按已有目录归入项目，没有目录的草稿继续独立显示。
- 会话首屏绘制完成即显示侧边栏，不再等待历史恢复和内置技能安装。打开会话或项目时先显示已保存内容，再恢复执行记录；恢复期间可编辑草稿，执行入口仍受恢复状态保护。
- 项目树只传递会话身份、标题和消息数量，避免展开节点时复制聊天正文。历史字节预算按不可变消息数组缓存；仅修改消息时重新计算。重复选择当前会话或模式不写盘、不触发树刷新；重新打开当前会话跳过执行恢复。相关回归测试见 `test/integration/extension/navigation-performance.cjs`、`test/harness/session/history-budget.cjs` 和 `test/integration/webview/render-performance.mjs`。
- 旧消息标识使用可复制的 SHA-256 前缀摘要批量生成，每条历史记录只序列化一次，与原有消息标识保持兼容。探索页按不可变来源缓存验收标准和笔记，流式更新跳过重复序列化及未变化的无障碍属性、进度属性。笔记列表先比较旧行内容和时间戳，仅为新增或修改的笔记创建节点，保留未变化行的焦点。
- 两侧标题栏提供收起按钮；主空间页头两端的侧栏按钮始终保留，可再次展开或收起对应侧栏。会话栏的放大镜打开原生搜索框，搜索当前模式的标题、消息正文、目标、验收项和笔记；选择结果后跳转，取消不改变当前会话。
- 会话列表使用 44 px 原生行高、36 px 圆角选中区域和 14 px 标题；当前会话以圆点与浅色背景标识，完整标题和消息数可悬停查看。中英文界面采用 Segoe UI / 微软雅黑字体链；协助输入与用户消息使用 13 px，回复正文使用 15 px。
- 左侧会话栏顶部可切换“协助 / 探索”（图标 + 短标签；栏宽不足 200px 时仅显示图标），空状态时也始终可用，支持键盘方向键与 Home / End。标题栏固定为「项目与会话」，模式由切换条表达；打开配置时标题变为对应页名。会话行在运行中显示「运行中」，项目下另一模式的会话以模式标签区分并降低对比度。底部管理条与标题操作在较宽时显示短标签，窄栏保持图标。主空间页头缩为 52 px。
- 主空间统一页头、按钮、输入框和字体层级，覆盖 Webview 默认的两侧 20 px 留白。协助消息与输入区使用同一阅读列；目标摘要、导航、正文和指令区使用同一内容网格。验收进度仅由用户确认的条目计算。窄窗口自动精简页头文案，长内容在所属区域滚动，模式切换和发送入口始终保留。
- 协助输入采用紧凑卡片：顶部添加上下文和文件标签，底部显示协助模式、模型设置与发送/停止按钮；输入随内容增长，长草稿在框内滚动，接近 8,000 字符时显示计数。Enter 发送、Shift+Enter 换行，中文输入法确认不会提交。执行中可编辑下一条草稿，只有点击停止按钮才会停止当前运行；旧请求的回执不会清除后来编辑的内容。用户消息使用与输入框对齐的浅色整行卡片。
- 文件标签区分自动编辑器上下文和主动附件。移除标签后，该会话不再自动带入文件内容，直到再次选择文件；工作区信息继续保留。文件选择器的晚返回结果只更新发起会话，并在提交时检查该会话是否仍存在、是否已开始执行。
- 自定义工作台主题：`themes/ubovm-light.json`；原生界面精简样式：`workbench/workbench.css`。
- 全局文件搜索、账户、运行与调试、扩展、源代码管理等通用导航隐藏，编辑器工具栏和菜单仅保留当前工作流需要的入口。顶部三个开关分别控制会话列表、终端面板、文件树；终端创建、关闭与命令执行能力保留。
- 原生 `PanelPart` 仅允许打开 `terminal`，忽略旧配置中的 Output、Problems、Debug Console 等面板选择。Output 与诊断服务仍在后台收集信息和日志，不会显示对应面板。
- 新建终端默认使用“当前系统终端”本地 Shell，终端工具栏与选择列表均优先显示本地入口。隐藏的底部面板不响应后台无焦点显示请求，手动打开仍正常工作。手动选择 `UBOVM SSH` profile 时，通过 `host/system/terminal-service.cjs` 将原生终端输入、输出与尺寸连接至独立的 `SSHCommands.openInteractive()` PTY。配置从本机用户设置与 SecretStorage 读取，不依赖模型配置。终端下拉菜单保留 SSH 连接，工具栏可选择任意已保存 SSH 主机；断线后需新建终端重连。
- 终端切换会跳过已销毁但关闭事件尚未送达的 Shell；延迟的 SSH 连接失败不会覆盖后来选中的终端。SSH 配置读取失败时，选择器仍保留本地 Shell 和配置入口；服务关闭后不会再弹出等待中的选择器。
- NPM Scripts 视图的扩展声明设为 `when: "false"`，同时隐藏旧配置中的 `npm` 视图；不依赖已弃用的 `npm.enableScriptExplorer` 设置。
- 主空间禁止手动分屏，编辑器最多保留主对话与固定右侧文件组，禁止额外列和嵌套分屏。文件以正式标签页打开，即使调用方显式要求 `preview: true`，也不会创建预览标签。
- 文件标签栏提供“占据主空间”，临时将文件编辑器组展开到整个主编辑区域；点击“恢复侧栏”恢复原分栏宽度。展开不会移动标签、丢弃未保存修改或重建对话，切回主对话也会恢复分栏。侧边栏与终端保持原有状态。
- 命令：`ubovm.openWelcome`、`ubovm.openAssistant`、`ubovm.newChat`、`ubovm.newGoal`、`ubovm.selectConversation`、`ubovm.setMode`、`ubovm.resetLayout`、`ubovm.openTerminal`、`ubovm.openLocalTerminal`、`ubovm.selectTerminal`、`ubovm.openSource`、`ubovm.showRuntimeInfo`
- 对话界面使用主题变量、CSP nonce 与消息白名单，不加载网络资源。
- 启动后主对话常驻，禁止通过关闭标签页、关闭全部编辑器或跨组移动操作移除；窗口重载后自动恢复。使用 `Ctrl+L` 聚焦主对话，`Ctrl+Shift+L` 或会话树标题栏的加号新建对话，已有会话继续保留并可从左侧切换。
- `harness/session/sessions.cjs` 在 workspaceState 的 `conversations` v3 中持久化当前模式、每种模式的最近会话和历史；自动迁移旧 `conversation` 数据，并把 v2 混合会话的聊天与目标拆分保存。每种模式独立保留最多 50 个会话，每个会话保留最近 40 条消息。当前会话以圆点标识，重启后恢复选择与消息。`list()` / 扩展导出的 `conversationList()` 只返回当前模式，传入模式参数可只读查询另一模式；跨模式 `select` 会被拒绝。
- `harness/config/model-config.cjs` 管理本机模型配置与 SecretStorage 凭据。点击配置入口或执行 `ubovm.configureModel`；Webview 状态不包含凭据，工作区设置不能替换端点或 MCP 命令。模型消息经过 Markdown 与静态 HTML 白名单渲染，工具输出保留纯文本；选中文件与当前工作区编辑内容作为有界上下文发送。
- `ubovm.openSettings` 打开主空间内的系统配置；`webview/settings/settings.html`、`webview/settings/settings.css`、`webview/settings/settings-ui.js` 在宿主组装页面时注入同一 CSP nonce。分组、下拉选项与默认值集中在 `harness/config/settings-schema.cjs`，服务商预设由当前安装 SDK 目录整理到 `harness/config/model-presets.cjs`；服务商切换联动协议、地址与模型参数，MCP 使用含协议下拉框的连接表单。默认值只补齐未配置字段，不覆盖已有值，也不自动写入设置。`harness/config/settings-config.cjs` 负责宿主校验、版本冲突检测、失败回滚和加密凭据。系统配置包含模型、SSH、搜索、摘要、思考Agent和执行Agent；打开系统配置或首次初始化时，左侧会话树切换为可点击的配置分组列表（`ubovm.selectSettings`），当前分组带“当前设置”高亮；MCP/Skills 页仍保留会话树（弱化显示）。左侧会话栏底部固定显示图标化的“管理配置”入口（MCP、Skills、系统配置，文字隐藏），分别调用 `ubovm.openMcp`、`ubovm.openSkills`、`ubovm.openSettings`。各页均接入真实配置读取。`settingsRead/settingsSave` 消息只返回公开值及凭据存在状态，密码留空不覆盖；运行前才在扩展宿主注入凭据。`summaryEnabled` 控制摘要启用并保留参数。桌面端始终启用全部内置工具，兼容忽略旧 `toolsEnabled`、白名单与工具关闭标记，保留连接参数和凭据。`settingsNavigation` 仅在 Webview 接受切换后更新原生底部入口选中态，未保存提示可取消切换；返回对话清除配置高亮。
- `src/harness/ide/runtime/harness-service.cjs` 连接真实执行器：协助模式调用 `agents/collaboration/index.mjs` 的 `runCollaboration`，由 Chat 对话按需派生 Swarm Worker；探索模式调用 `createHarness`，继续使用 Reason/Worker 黑板调度。`swarm.status` 提供任务动态，`swarm.worker.event` 只把子 Worker 的工具事件投影到时间线；主对话正文与最终回复由 Chat 提供。会话模式标识仍为 `assist`，沿用已有历史和 `assist.sqlite`。`ubovm.runGoal/cancelRun/resumeRun` 提供开始、停止和恢复，界面显示真实状态、工具活动和证据。运行中可切换会话，后台回复按原会话 ID 保存；过期会话的前台写入会被拒绝。
- 目标使用 SQLite 检查点，重开后只恢复显示，点击继续后才执行。协助保存独立 SQLite 历史、工具记录与摘要。MCP、Skills 和摘要由本机配置接入，基础工作区工具只读，桌面编码工具另外提供带版本检查的编辑、持久化 diff 和撤销。运行需要工作区信任，修改运行中目标前须先停止。
- 目标在读取模型配置前持久化待执行输入，恢复时按输入版本与黑板修订号判断继续执行或补发已完成结果。协助沿用 `worker.maxModelCalls/maxToolCalls` 调用预算，默认 `0` 表示不限次数；中断记录保存有界的实际工具参数，超限不会继续调用模型掩盖错误。
- 高频执行状态通过 `host/agent/state-publisher.cjs` 合并，只传输当前会话的执行增量，不重复携带历史消息；隐藏窗口、设置页与后台会话不推送流式更新，重新显示时补齐状态。流式文本先保留最新值，在实际发布或工具、消息边界时处理，避免每个 token 重复扫描和脱敏整条时间线。
- 主页面同一帧只渲染一次，目标黑板、笔记与聊天内容在选中时更新。流式文本不重建已有消息，自动滚动校验当前会话、目标标签和阅读位置。输入草稿延迟 180 ms 合并保存，切换会话、失焦或离开页面时立即保存；等待恢复时保留草稿，并阻止按钮或 Enter 提交与恢复冲突的新请求。
- Worker 日志与黑板详情分别维护有界异步发送队列：一次发送期间仅保留最新待发布状态，慢侧栏不阻塞主对话流式更新；关闭、隐藏 Worker 或重建组件会释放旧队列，迟到回调不能干扰新组件。Worker 就绪后即可完成导航，无需等待日志发送队列排空；日志增量按动画帧合并，会话切换及显式选择立即生效，并丢弃旧帧。
- 黑板详情返回文件时不等待主对话消息回执，通知失败单独记录；组件被替换后，旧导航不能再次展开新详情。SSH 测试的总超时覆盖模块加载、连接与清理，即使底层异步调用不响应取消也会释放测试状态；关闭组件后迟到的模块加载不会建立新连接，连接清理只启动一次。
- 会话首屏和设置初载显示骨架，数据到达即撤下；目标各标签显示实际执行状态。配置刷新保留原表单，按配置指纹复用分栏节点，保留滚动、展开项和焦点；加载失败可重试，已关闭页面的迟到回包不会重新打开页面。新增动画仅使用透明度或变换，并遵守减少动态效果设置。
- `webview/messages/message-markdown.js/.css` 使用随扩展打包的 Marked 解析 GFM，支持标题、列表、任务清单、引用、表格、链接和代码高亮。代码卡片提供语言、复制、长代码展开与 HTML 预览；未闭合代码围栏保持同一节点，流式追加不重置已完成段落、代码展开状态与选区。解析结果只创建白名单 DOM，图片与远端资源不会自动请求。
- `webview/messages/message-view.js/.css` 将 `execution.parts` 和历史 `message.parts` 渲染为正文与嵌入式工具卡片交错的时间线。连续调用共用一组轻量边框，每行展示工具类别、动作、目标、真实状态与耗时；展开后优先显示纯文本输出，参数独立折叠。失败时保持原有展开状态，不自动展开；可手动展开查看原因，后续更新保留用户选择；复制等待宿主回执，HTML 通过隔离预览打开。文件工具可在指定工作区打开原文件，多根工作区不会串到同名文件。追加日志保留文本节点、选区与阅读位置，只在读者已处于底部时跟随新输出。SSH 与本地技能脚本按实际分块累积有界日志，MCP 进度继续按快照更新。执行结束复用流式消息节点，取消保留中断状态，历史与 Goal 补投递保留相同片段 ID；Goal 内部协议不进入正文。
- 模型实际返回的明文 thinking 使用独立的 `type: 'thinking'` 时间线片段，记录来源、运行/完成/中断状态及有据可查的时间。思考默认展开并按安全 Markdown 渲染，手动收起后保留用户选择；细左线和次要文字与正式回答区分，展开、选区及局部滚动在流式更新和历史转存时保留。收起时延迟解析，纯思考阶段不显示正文输入光标。Reason 和 Worker 分别标明来源，思考不会拼接进 `streamText` 或最终回答；签名、加密及被标记为 redacted 的内容不进入界面。单个思考片段最多保留 12,000 字符，并与工具、正文共享时间线预算，优先保留最终回答。
- `webview/preview/html-preview.js/.css` 提供隔离的静态 HTML/CSS/SVG 预览、源码切换、复制与键盘焦点管理，iframe 使用空 sandbox 和独立 CSP。脚本、表单、导航与外部资源禁用。`harness/session/message-actions.cjs` 将复制交给系统剪贴板，将外链交给系统浏览器；源码链接经工作区边界与 realpath 校验后打开到指定行列。

## 开发与原生工作台

主启动脚本会把本目录复制到 Code OSS 运行时的 `resources/app/extensions/ubovm-core`，作为内置扩展运行。开发时也可以用 `--extensionDevelopmentPath=<本目录绝对路径>` 加载；修改 JavaScript 后执行「开发人员: 重新加载窗口」。

根目录的 `resources/patches/core-ui.patch` 修改 Code OSS 的 Webview 编辑器输入，为主对话增加 `CannotClose`、`ExcludeFromEditorLimit` 和跨组移动限制；`resources/patches/minimal-ui.patch` 精简原生菜单并拦截手动分屏等命令；`resources/patches/editor-layout.patch` 在核心编辑器服务中限制组数量、方向与嵌套布局。`resources/patches/conversation-chrome.patch` 移除主对话的原生标签和标题栏并重新计算布局高度；`resources/patches/terminal-panel.patch` 将底部原生面板限制为终端。`workbench/workbench.css` 负责收起剩余原生工具栏入口，同时保留文件标签关闭按钮、文件操作、终端与窗口控制。

`resources/patches/session-list.patch` 仅为 `ubovm.sessions` 设置更宽松的虚拟列表行高和专用样式类；文件树仍使用原有行高。行高由核心布局管理，滚动、命中区域和键盘导航与视觉位置保持一致。

`resources/patches/sidebar-mode.patch` 在会话视图顶部加入原生模式切换按钮，底部固定显示图标化的“管理配置”入口（MCP、Skills、系统配置，约 40px，文字隐藏保留悬停提示与无障碍标签；不出现滚动条；与模式区合计约 90px，需与 `workbench.css` 同步），为欢迎页和虚拟列表预留上下导航空间。会话栏标题「+」展开菜单可选新建对话/探索或新建项目；对话页顶栏「+」同样提供这两项；项目管理使用对话页居中的可搜索切换弹窗（类似 Cursor）：支持搜索、当前项目高亮、新建/打开/重命名/删除；Webview 未就绪时回退到居中 QuickPick。新建项目也可在弹窗内完成（建议目录或浏览）。模式通过 `ubovm.setMode` 切换，监听 `ubovm.mode` 上下文同步选中状态；管理入口监听 `ubovm.settingsPage`，仅在 Webview 确认导航后更新选中态，不替换会话树。空会话欢迎页和配置页面始终保留两个模式按钮；在配置页点击模式会先返回对话，再按需切换模式。按钮与监听器随视图销毁，不在主 Webview 中重复显示。`node src/renderer/test/workbench/sidebar-navigation.mjs` 使用原生样式和实际补丁脚本覆盖启动、欢迎页、配置导航、侧栏收放及样式加载顺序。

`resources/patches/panel-ui.patch` 为侧栏和终端提供 140 ms 进入过渡。收起时直接提交原生布局，不再克隆整栏 DOM；快速切换仅取消本栏自己的动画，减少动态效果时跳过。文件与会话栏沿用原生加载进度，模式及管理入口显示实际命令执行状态。终端在进程与 xterm 尚未就绪超过 120 ms 时显示细进度条，隐藏、切换、完成或销毁时清理。文件欢迎页区分无工作区与单个空文件夹；扩展监听文件事件更新上下文，创建首个文件后恢复原生文件树，删除最后一个文件后恢复欢迎页。首次自动创建的空会话作为占位，不进入历史列表或搜索；发送消息、保存目标或手动新建后才显示，旧历史不会被隐藏。

`workbench/startup.html` 包含首帧即可显示的浅色品牌画面、标志微动和不定进度动画，由 `build.bat` 注入原生 `workbench.html` 与 `workbench-dev.html`。`resources/patches/startup-ui.patch` 在 `PartsSplash` 收到首次真实工作台布局事件后触发 180 ms 淡出，并移除启动 DOM 与样式；不设置最低展示时间或模拟百分比。`prefers-reduced-motion: reduce` 下禁用动画，在布局就绪时立即清理。该补丁也将内置 npm 扩展的脚本视图声明设为不可见。

`build.bat` 在源码编译前应用以上补丁、样式和启动 HTML，并在准备固定版本的预构建运行时时应用对应改动。源码提交、补丁适用性、下载包 SHA-256 和运行包代码位置检查继续生效；脚本会为修改后的工作台 HTML、脚本和样式更新产品校验值，保持完整性检查正常。常驻布局由扩展与核心共同实现；仅将扩展加载到未经补丁修改的其他 VS Code 安装中，不具备核心级关闭与分屏保护。

项目的 Electron 主进程入口为 `src/main/index.mjs`；它转发到真实的 Code OSS 主进程。`runtimeInfo().entryPoint` 显示主入口标记，使用上游源码开发模式时显示 `upstream source`。

持久化根目录由 `src/main/data-paths.mjs` 统一为 `~/.ubovm/`，正式、源码、测试环境分别使用 `desktop`、`source`、`smoke`。`workspaceState`、Webview 草稿、用户设置、SecretStorage、备份及 `context.storageUri/harness` 随 Code OSS 的 portable profile 一起迁移；扩展不另建一套存储路径。`runtimeInfo().persistence` 可查看当前实际路径。启动脚本和直接启动 exe 都在创建新 profile 前尝试迁移本项目旧 `.data/<profile>`，保持源目录备份，拒绝覆盖已有目标和迁移活动目录。

探索图支持按事实内容、意图描述、提示、关注点或节点 ID 搜索，按 Enter 或“下一项”循环定位匹配结果并打开详情。选择节点或意图后，可切换“追溯上游证据 / 追踪下游分支”，无关路径会淡化；“全部路径”恢复显示。执行中的意图定位到待产出节点，完成后定位到产出事实；实时更新保留搜索和追踪模式，切换会话时重置。路径追踪支持分叉、汇合和循环关系，不改动持久化事实或调度状态。

连续的上下文整理和 `wait_workers` 调用在消息中合并为一条可展开状态，原始调用、摘要和错误仍保留在详情中；失败时不自动展开分组。只有时间线末尾正在输出非空正文时显示输出光标，已有内联运行状态时不重复显示底部执行指示。此合并仅影响展示，不改变执行记录或等待时限。

上下文摘要使用与 thinking 相同的轻量折叠区域，默认收起，展开查看实际摘要、估算的上下文 token 用量变化和耗时。摘要中间件仅在生成新摘要时发布 `context.summary_start` / `context.summary_end`，一次整理内的多个分段共用一个提醒；缓存命中和已整理上下文不会重复触发。使用原文摘录的降级结果会明确标注，失败与取消分别显示未完成/已停止。`type: 'summary'` 片段沿用脱敏、12,000 字符和时间线总预算，随历史保存；Worker 的摘要保留在对应 Worker 详情内。

`node --test src/renderer/test/host/agent/state-publisher.cjs src/renderer/test/harness/runtime/harness-streaming.cjs src/renderer/test/integration/webview/render-performance.mjs` 验证高频更新合并、隐藏与后台会话暂停、消息桥背压、流式工具顺序与取消、协作和目标的独立执行入口、子 Worker 工具投影与正文隔离，以及真实浏览器中的首屏加载、选区保留、目标标签按需渲染、草稿保存和减少动态效果。浏览器测试使用本机 Edge，可通过 `UBOVM_STYLE_EDGE` 指定路径。

页面静态资源在扩展宿主生命周期内读取、拼接一次，重新打开面板仅替换工作区名称、版本和独立 CSP nonce；开发时修改页面资源后需重新加载扩展。流式执行更新复用历史消息投影，不重复遍历已发布历史；完整状态仍会核对历史修改和删除。Worker 目录及未选中的概览页面延迟渲染，重新打开时立即补齐最新状态；隐藏列表暂停计时文本更新，未变化的日志保留标题与交互节点。`webview.cjs` 和 `render-performance.mjs` 的测试覆盖资源读取次数、历史访问次数、隐藏区域 DOM 变更和展开后的新内容。

历史执行记录的并发读取共用一次恢复任务，读取完成后才标记为已恢复；失败会传递给所有等待者，后续访问可重试。旧消息缓存若只保留工具、思考或摘要片段而缺少非空正文片段，页面会补显保存的消息正文；已有正文片段的时间线和流式输出保持原有显示逻辑。`worker-views.cjs` 与 `tool-cards.mjs` 覆盖并发恢复、失败重试、旧缓存正文补显和切换会话后的显示。

Worker 缓存读取失败不阻塞主历史，后续恢复仅重试 Worker 记录，成功后清除错误并保留数据库中的目标状态。旧 Worker 缓存缺少正文片段时，会将已保存的结果或部分输出恢复为经过脱敏的正文片段，重载不会重复追加；只有工具记录时不插入“没有更多执行记录”的占位文案。`worker-views.cjs` 和 `worker-panel.mjs` 覆盖这些恢复与显示路径。

桌面端点击 Worker 卡片或执行日志入口，会打开 VS Code 右侧原生侧边栏中的“Worker 日志”（`ubovm.workerLogs`）。面板与会话栏、编辑区由工作台统一布局，不占用主对话网页的布局；尺寸和显隐由 VS Code 管理。主对话不可见时，已打开的日志面板仍接收合并后的实时更新；面板隐藏后暂停发送，重新显示时补齐最新状态。切换会话会清除旧 Worker 的选择与日志，Worker 内切换保留工具展开和阅读位置。`node --test src/renderer/test/integration/webview/native-worker-panel.mjs` 验证原生消息桥、隐藏恢复、会话隔离和独立日志页面。

完整历史刷新按消息 ID（旧消息回退至首个片段 ID）复用节点，补载和裁剪消息不会将已有工具卡片误配给另一条消息。先移除过期记录再调整顺序，保留未移动消息的展开状态和文本选区；流式回复转存时核对位置，内容相同的旧回复不会抢占新回复节点。无标识的旧纯文本消息仍兼容按位置更新；仅执行状态更新继续跳过历史遍历。

扩展关闭会等待已启动的历史恢复（包括尚未建立会话的工作空间查询）结束，再保存 Worker 投影并释放资源。关闭期间不再注册会话，等待历史恢复的开始/继续请求也会终止，避免异步加载在关闭后重新建立状态。`worker-views.cjs` 覆盖首次加载时关闭、数据库慢恢复时关闭，以及关闭后重新打开仍能读取原记录。

删除会话和释放工作空间同样等待该会话已有的恢复任务结束，期间拒绝同一会话的新恢复、执行和重复切换请求；其他会话仍可加载。删除目录前会完成工作空间标记写入和历史恢复，避免首次加载与目录删除相互覆盖；扩展关闭也会等待这些清理操作结束。

同一会话更换目标、模式或执行目录时，先等待旧历史恢复结束，再保存旧投影并替换会话实例。并发请求共用旧实例的清理过程，并重新核对当前实例，避免重复关闭、删除其他请求刚建立的实例，或让旧请求返回新目标的状态。

已发布历史消息还会核对保存正文与时间线的完整性：只有开场说明和工具记录时补显最终正文，最后正文片段仅为保存正文的前缀时补全该片段。正文已跨多个片段展示、或时间线比带显示截断提示的消息正文更完整时不重复追加。补显只作用于渲染投影，不改写缓存；流式输出与执行日志保持原有逻辑。

已完成 Worker 的列表预览和详情优先采用保存的最终结果，避免旧流式预览或最后一次工具调用遮住结果。详情沿用历史正文完整性校验，片段后续补齐时去除补显正文，并保留工具卡片展开状态；运行中的 Worker 仍按流式进度显示。

`node --test src/renderer/test/harness/config/settings-config.cjs` 验证配置持久化、运行时凭据注入、SSH / MCP 端点隔离、密钥清除与旧配置迁移、摘要开关保留参数、旧工具开关迁移、冲突拒绝和失败回滚，不调用外部服务。

# 聊天内工具审核

会话是执行与审核的隔离边界：每个会话拥有自己的后台 Agent 运行、取消信号、审核请求和结果回写。同一会话内的 Agent 可以协作；切换会话只改变当前查看的内容。停止或删除某个会话不会停止其他会话的 Agent，也不会批准或取消其他会话的审核。`worker-views.cjs` 覆盖两个会话使用相同 Worker / 工具调用标识时的并行运行、停止、删除、审核与回复归属。

探索模式与协助模式切换属于会话导航，不是修改运行中会话的执行模式。两种模式各自记住选中的会话，切换不发送停止或审核决定；后台回复仍写入原会话，切回后显示最新进度及尚未处理的审核请求。从配置页切换时，目标模式随关闭请求传递，只有配置页确认关闭后才执行；选择继续编辑会取消切换并保留输入。确认携带发起时的会话标识，过期的确认不能切换后来选中的会话。`session-modes.cjs` 和 `tool-cards.mjs` 覆盖运行中双向切换、后台回写及待审核状态恢复，`settings-ui.mjs` 覆盖未保存修改时的取消和确认流程。

同一会话的每轮执行还拥有独立的事件归属标识。结束或停止后的迟到回调不能修改已保存结果或下一轮的正文、Worker 和工具状态，也不能创建新的审核请求；异步清理开始前即失效旧回调。协助与探索模式共用这一检查，不影响当前轮次内的 Agent 协作。

启动准备阶段在目录准备、工具装配、工作空间读取和目标输入提交完成后重新检查停止信号。准备期间停止任务后，不再调用协助模型或创建探索运行时；探索模式保留可继续状态，协助模式可重新提交，其他会话继续运行。每次启动复用同一次读取的工作空间列表来配置工具与模型。

人工审核模式下，工具调用使用紧凑的聊天内卡片：直接预览命令或参数，次要位置显示工具名和执行者，完整参数默认折叠，底部提供“允许一次”和“拒绝”。提交期间禁止重复点击，失败时在卡片内提示重试。宿主确认已允许、已拒绝或已取消后，卡片从聊天中移除，刷新也不会重新显示；待处理请求继续保留。批准仅作用于该次调用，多个 Worker 的请求可独立处理。卡片适配浅色、深色和 320px 窄屏，不额外打开审核页面。

待审核请求由宿主保管，切换会话或重新加载聊天视图后可以恢复；停止任务或扩展退出会取消待处理请求，过期、重复及跨会话操作不能批准执行。已处理的审核卡片最多保留最近 100 条，仅在当前扩展运行期间保存。

当前会话的未审核卡片不会因普通刷新漏带审核记录、临时空列表或执行转为空闲而消失；即使聊天没有正文，也会保持可见。只有收到该请求明确的允许、拒绝或取消状态才移除。切换到其他会话时不会显示上一会话的卡片。

概览日志按实际显示字段比较变更，不再为每个流式更新序列化全部历史工具输出；正文与标题独立更新，删除记录或切换会话时释放消息计时器。活动去重使用工具名集合，避免逐条遍历全部日志。探索模式单次渲染超过 8ms 时，后续流式刷新通过定时器与动画帧合并，让出最多 250ms 的间隔处理输入和滚动；只保留最新状态。完整刷新、页面导航及执行结束绕过间隔，隐藏页面和打开配置时取消待执行定时器，恢复后补齐最新内容。`render-performance.mjs` 覆盖 200 条长工具日志的增量更新、重渲染让出主线程、最终输出与会话切换。

页面 `pagehide` 与后台隐藏共用可视任务暂停规则：取消渲染、输入尺寸、最新消息按钮、焦点及首屏确认的待执行动画帧；新状态只缓存，恢复时合并绘制最新状态，首屏确认不重复发送。原生 Worker 日志保留暂停前未绘制的快照，隐藏期间导航先使旧操作失效，恢复后再绘制；失败重试优先使用最新待绘制状态，避免旧失败快照覆盖新结果。Worker 名称与父子关系使用每次快照建立的索引。拖入文件的异步读取绑定独立操作及页面代次，跨会话切换或暂停后失效，旧读取的结束回调不能解锁新的读取。

Worker 列表只写入发生变化的文字与属性，切换器按 Worker ID 复用选项，删除旧行时保留仍存在行的键盘焦点。卡片预览最多读取所需的 150 字符摘要，保留完整 Unicode 字符，创建时间按原始值缓存格式化结果。`worker-panel.mjs` 验证 100 个 Worker 连续 100 次仅日志变化时列表与选项无 DOM 改写，以及名称、状态和删除更新。HTML 预览的按钮与异步复制结果绑定当前预览实例；关闭、替换或页面离开后旧操作失效，清理焦点定时器，复制返回失败不会显示成功。`tool-cards.mjs` 覆盖重复点击、旧弹窗事件与迟到回执。

探索画布在页面暂停、后台隐藏或配置窗口打开时停止布局和标签测量，取消拖拽、缩放标签及尺寸变化的待执行动画帧，并释放指针捕获。暂停期间只保留最新快照，恢复后重绘最新内容；销毁后拒绝旧更新、选择及按钮事件，移除生命周期监听器。`blackboard-graph.mjs` 覆盖暂停期间 1,000 次更新不投影、不改写 DOM，恢复只投影最新快照，以及销毁后的迟到调用。

Worker 日志与黑板详情的状态发布设置 5 秒超时，同一视图实际未结束的发送最多 4 条，排队更新仅保留最新任务。超时后可推进下一份快照；达到实际容量时等待旧发送结束，再读取最新状态。桥接返回 false 明确报告发送失败，迟到结果不会二次报告或干扰替换后的视图。替换和关闭视图逐项释放订阅，同步异常、异步拒绝及错误观察器失败均不会跳过其他清理。

原生 Worker 页面最多保留 32 个待回应的手动操作。桥接返回 false、同步抛错或异步拒绝立即结束对应等待；隐藏页面与 pagehide 取消等待并使旧复制提示失效。渲染帧附带代次，即使取消后的回调迟到，也不能消费恢复后的快照或清除新帧。Worker 消息验证会话 ID 和列表形状，黑板详情在替换当前状态前验证每条正文与关联节点记录，异常数据不覆盖可读内容。

文件管理保留文件名搜索、工作区内容查找与替换，标题栏提供快速打开、查找内容和替换内容入口。Ctrl+P 搜索文件，Ctrl+Shift+F 查找工作区内容，Ctrl+Shift+H 打开工作区替换；编辑器内 Ctrl+F / Ctrl+H 保持可用。文件夹右键查找、正则、大小写、全词匹配及搜索结果替换操作同时保留。源码与预构建版本共用 file-search.patch 中的菜单、命令与快捷键规则。

查找栏完整保留原生 FIND_IDS 操作，包括从选区查找、前后匹配、跳转匹配、替换当前项、全部替换、选择所有匹配，以及关闭查找栏和匹配选项。预构建版快捷键规则升级先核对唯一托管入口和原有行为，再替换搜索允许列表；多重入口或未知规则明确拒绝，避免重复打补丁后悄悄失效。

后端 search_workspace 在任何异步准备前预留并发名额，默认全局最多 4 个、每会话最多 2 个搜索。取消、超时或异常输出先停止进程；1 秒内仍未关闭则结束调用并保留原错误，物理进程继续占用名额，直到 close 或确定启动失败。关闭后回收名额，迟到输出不再解析。搜索前后核对会话工作空间，切换目录后拒绝旧结果。结果同时校验路径范围和 realpath，目录链接与路径穿越不能暴露根目录外的文件。这些限制作用于 Agent 后端只读搜索，不改变原生编辑器替换操作。
