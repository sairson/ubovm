# UBOVM

面向 **渗透测试、CTF、代码审计和编码** 的桌面 IDE。工作台基于 VS Code / Code OSS，Agent 在同一窗口里读代码、跑命令、记证据、改文件。

明确的 CTF / 授权安全任务默认视为赛题范围：优先用已配置的 **远程 Linux SSH** 做侦察、验证与拿 flag，本机 Shell 只用于看代码、改代码和搭环境。授权不会延伸到无关的真实系统。

```text
项目与会话 | 主对话 | 文件编辑 | 文件树
协助 / 探索   模型 · 工具审批 · 工作空间 · SSH 终端
```

| 模式 | 更适合 |
| --- | --- |
| **协助** | 审计源码、改代码、解题对话、边想边验证 |
| **探索** | 有目标与验收项的长任务：攻击面盘点、多 Worker 并行、黑板沉淀事实 |

首次启动先配模型和 SSH。密钥进系统凭据库；SSH 主机是执行环境，不等于题目目标，地址和端口以任务证据为准。

## 渗透测试

把授权范围内的 Web / 主机测试做成可追踪的工作流，而不是一串散落的命令。

- **远程 Linux 优先**：侦察、枚举、扫描、探测、漏洞验证走 `run_linux_ssh_command`；可用命名会话保留 cwd 与环境变量，长任务可中断或放到后台。
- **攻击面台账**：`domain_inventory` 从种子域展开子域、证书 SAN、DNS 别名、HTTP 跳转；相关主机默认在范围内，覆盖未完成不能当作安全交付已验收。
- **浏览器与被动情报**：内置浏览器打开页面、抓 DOM；`fetch_web_content` / `web_search` 做公开内容与被动检索，需要落地验证时再上远程命令行。
- **带外检测**：Skills 可接 ceye.io 一类 DNSLog，用于盲 SSRF、XXE、命令注入、SQL 注入等无回显场景。
- **资产与漏洞笔记**：会话笔记区分普通记录、资产、漏洞候选（含目标、向量、严重级别、证据与利用链提示）；可提升到探索黑板，候选不等于已确认 Finding。
- **人工审批**：默认每次工具调用先「允许一次 / 拒绝」，高风险命令看得见再执行。

独立审计或渗透任务不必走新项目交付台账；交付闭环只用于「新开发项目」里开发 → 审计 → 安全 → 部署 → 运维的阶段验收。

## CTF

针对题目分析、利用调试和 flag 核验，而不是通用聊天。

- **赛题范围**：题目文件、本地环境和指定靶机视为已授权，Agent 不会反复追问权限或插入免责声明。
- **默认远程解题**：枚举、扫端口、漏洞验证、payload、取 flag 优先在 SSH 的 Linux 上完成；需要把附件或脚本送上去时用 SFTP，不要假设本机路径在远端存在。
- **本地只做配套**：用工作区打开附件、写 exploit、反汇编注释、补脚本；Python 沙箱跑加解密、编码转换、协议草稿。
- **证据链**：工具输出进时间线；探索模式用黑板记录事实 / 意图 / 待补证，路径追踪可以顺着证据往上或往下走。
- **协作**：主 Agent 可派 Worker 分头看附件、写脚本、在远端验证，结果和工具日志仍归同一会话。

SSH 连不上或缺工具时会说明具体限制，并改用允许的替代路径，不会把远端操作偷偷改成本机扫描。

## 代码审计

在编辑器里读项目，用 Agent 做有证据的审查，而不是只摘要源码。

- **只读检索**：工作区搜索（ripgrep）、按文件分页读代码、语言服务诊断；编译检查是受限的 no-emit，不执行用户脚本。
- **结构导航**：跳转定义、调用链、重命名预览、项目说明（如 `AGENTS.md`）随读取注入，便于顺着数据流和鉴权路径看。
- **选区进对话**：编辑器里选中代码可附加到当前会话，提交时用当时的快照，不会在发送后再读一遍整文件。
- **发现要落盘**：漏洞候选必须带 effects 与 evidence；删除笔记要写原因。探索模式可把已闭合的事实升到黑板。
- **和渗透衔接**：审计出的假设用远程命令或浏览器再验证；修复走编码工具，本轮 diff 可复查、可撤销。

协助模式适合对着单个模块深挖；探索模式适合「覆盖这些路由 / 把高危清掉」这类带验收项的审计任务。

## 编码

原生编辑器改代码，Agent 的写入可追踪、可撤销。

- **精确编辑**：先 `read_workspace_code` 再按 hash 创建、替换、多处 patch 或按范围改；也可一次预览最多 20 个文件再提交。
- **本轮变更**：回复下方汇总增删行，点文件名打开原生 diff，可一键撤销本轮工作区 UTF-8 修改（不含 SSH / 终端 / Python 的副作用）。
- **本机开发循环**：`run_local_shell_command` 只用于检查、构建、测试、调试和装依赖（Windows 为 PowerShell）；`npm run dev` 一类命令可驻留，停止本轮对话不会杀掉进程。
- **Python**：内置解释器在沙箱里跑脚本、管依赖，不改系统 Python。
- **验证**：保存前记诊断基线，改完再跑检查；Agent 不能把「文件已写入」说成「测试已通过」。
- **新项目交付**（可选）：开发 / 审计 / 安全 / 部署 / 运维分阶段验收，安全和部署阶段要有真实执行证据；攻击面未覆盖完不能过安全关。

本地 Shell 不能用来做通用浏览、绕过远程工具限制，或把渗透步骤改在本机执行。

## 共用能力

四种工作都走同一套运行时：

- 多项目、每会话独立工作空间（默认 `~/.ubovm/workspace/<会话ID>/`）
- 工具时间线、思考过程、上下文摘要；运行中可排队下一条输入或「引导」改方向
- Swarm Worker、待办、MCP、Skills；执行经验后台写入 `~/.ubovm/learning/`，只作参考，不扩大权限
- 底部终端：本机 Shell 或已保存的 SSH 主机，与 Agent 使用同一套远程配置

## 开始使用

**安装包**：Windows x64 安装后启动 `UBOVM.exe`，数据在 `~/.ubovm/desktop/`。

**源码**需要 Node.js 24（`< 25`）。Windows 用 PowerShell；macOS / Linux 需要 `pwsh`。

```sh
npm install
node build.mjs setup    # 准备桌面运行时
node build.mjs start    # 启动
```

建议先配 **模型**，再配 **SSH**（CTF / 渗透的默认执行环境），然后按需打开浏览器、搜索、DNSLog、MCP。`node build.mjs dev` 从 `src/renderer` 加载界面；`node build.mjs help` 查看安装包、检查与测试命令。

## 数据与边界

| 内容 | 位置 |
| --- | --- |
| 配置、会话、凭据 profile | `~/.ubovm/desktop/` |
| 默认工作空间 / 学习库 | `~/.ubovm/workspace/`、`~/.ubovm/learning/` |

API Key 不进页面；工作区工具受目录与 realpath 约束；审批、停止、删除以当前会话为界。题目文件和工具输出都是不可信证据，不能自行扩大范围。

工作台扩展（`src/renderer`）为 MIT；内核遵循 VS Code / Code OSS 许可。
